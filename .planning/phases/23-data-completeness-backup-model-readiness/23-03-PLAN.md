<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions secrets store → workflow env | Secrets are injected only via the `env:` block scoped to the backup step, matching the existing `ORACLE_SSH_KEY`/SMTP-secret pattern already in this file |
| OCI bucket visibility | A public bucket would expose all historical vol-diagnostics data to anyone with the bucket name/namespace |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-07 | Information Disclosure | OCI bucket visibility | mitigate (human-verified) | ORACLE-CLOUD-SETUP.md instructs the bucket be created as Private, in bold; the checkpoint task explicitly asks the human to confirm this was followed — Claude cannot query bucket ACLs without credentialed OCI access, so this cannot be automated end-to-end |
| T-23-08 | Spoofing | GitHub secrets exposure in logs | mitigate | Secrets are referenced only via `${{ secrets.NAME }}` inside an `env:` block (GitHub automatically masks secret values in logs); never interpolated directly into the `run:` command string |
| T-23-09 | Tampering | Backup step running with `if: always()` after a failed collection | accept | Intentional — per D-07/the existing `Push updated history` step's own `if: always()` precedent, a partial/failed collection run should still back up whatever did save rather than skip the backup entirely |
</threat_model>
