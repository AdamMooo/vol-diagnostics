    backfill(ticker: str, start_date: datetime.date) -> None:
    - Calls list_available_dates(ticker) to get all stored dates (descending)
    - Filters to dates >= start_date; reverses to process oldest first (progress clarity)
    - For each date in the filtered list: call update_evolution(ticker, date).
      DO NOT add an inner loop over HORIZONS — update_evolution already iterates all of HORIZONS internally. backfill's loop is: `for date in reversed(filtered_dates): update_evolution(ticker, date)`.
      This is the consistency guarantee: backfill and daily ingestion use exactly the same code path.
    - Wraps each update_evolution call in try/except; on failure prints f"  [WARN] {ticker} {date}: {exc}" and continues to the next date
    - Progress output format:
        Per date (on success or skip): f"[backfill] {ticker}: {date} -> rows written"
        On try/except catch: f"  [WARN] {ticker} {date}: {exc}"
        Final summary: f"[backfill] {ticker} complete ({n} rows)" where n is the count of dates processed without exception
    - Does NOT call compute_evolution_scalars directly — all scalar logic is inside update_evolution

    __main__ block at bottom of surface_evolution.py:
      if __name__ == "__main__":
          import argparse
          parser = argparse.ArgumentParser(description="Surface evolution backfill utility")
          parser.add_argument("--backfill", action="store_true")

          parser.add_argument("--start", type=datetime.date.fromisoformat, default=None)
          args = parser.parse_args()

              start = args.start or (datetime.date.today() - datetime.timedelta(days=90))
              backfill(args.ticker, start)
          else:
              parser.print_help()

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-06 | Denial of Service | run_daily evolution pass blocking email | mitigate | per-ticker try/except in run_daily wraps update_evolution; failure prints WARN and continues; email send is downstream of the loop |
| T-09-07 | Tampering | backfill --ticker CLI arg | accept | ticker arg is passed to list_available_dates which constructs a path via _store_path(ticker); _store_path uses STORE_DIR / f"surface_{ticker}.parquet"; no shell expansion, no path traversal beyond the out/surface_history/ directory |
| T-09-08 | Tampering | backfill --start date arg | accept | parsed with datetime.date.fromisoformat; malformed input raises ValueError (argparse exits cleanly); no eval |
| T-09-SC | Tampering | npm/pip/cargo installs | accept | no new packages; existing stack only |

All I/O is local parquet files within the project's out/ directory. No network calls, no eval/exec, no untrusted deserialization beyond the existing pyarrow stack.
</threat_model>
