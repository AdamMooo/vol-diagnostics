# Phase 18.1: Dashboard Trust and Clarity Hardening - Context

**Gathered:** 2026-06-23
**Status:** Ready for planning

<domain>
## Phase Boundary

Tidy and harden the current dashboard presentation so PM-facing reads are more
trustworthy, consistent, and decision-useful without adding net-new analytics
domains. Scope is display logic, metric framing, and dealer-relevant tenor
policy for existing data paths (VRP, OI, GEX, Evolution, scorecards).

</domain>

<decisions>
## Implementation Decisions

### VRP trust framing
- **D-01:** Keep VRP available, but make trust state explicit in the UI (history vs
  building) using sample-count-aware labels.
- **D-02:** VRP is demoted when history is still building; it should not be presented
  as a top-confidence read during thin samples.

### OI story and context
- **D-03:** OI presentation is table-first. Remove confusing shape/overlay cues from
  the OI view and rely on explicit columns.
- **D-04:** OI impact table must include expiry context and accumulation context:
  Expiry, DTE, OI, Δ OI, OI Share, 5d Avg Share, vs 5d Avg, P/C Ratio, Impact.
- **D-05:** Stored OI history is required input to OI interpretation; OI narrative
  cannot rely only on same-day values.

### GEX dealer-impact tenor policy
- **D-06:** Primary dealer-impact horizon is **14 DTE** for positioning views.
- **D-07:** Broader horizons can remain available as secondary context, but the
  default framing and top-level narrative must use the 14 DTE lens.

### Methods & assumptions usability
- **D-08:** Replace essay-like methods content with a compact “quick assumptions”
  summary first, with expandable deeper detail.
- **D-09:** Methods content must be adjustable by depth (quick vs detailed), not a
  single long static block.

### Evolution signal clarity
- **D-10:** Add a plain-English “what changed most today” summary row as the default
  Evolution upgrade.

### Scorecard information hierarchy
- **D-11:** Default scorecard is compact (6 key fields) with trust tags and
  expandable details for secondary fields.
- **D-12:** Primary card fields must optimize for actionability over exhaustiveness.

### Claude's Discretion
- Exact wording for trust labels and quick-methods bullets.
- Exact threshold bands for OI impact wording, as long as they remain descriptive
  and consistent with existing raw metrics.

### Folded Todos
- **v3.2 — Pre-Distribution Hardening (audit follow-ups)** (from
  `.planning/todos/pending/2026-05-11-v3-2-pre-distribution-hardening.md`) is folded
  into this phase only where it supports trust/clarity hardening and display
  reliability; unrelated legacy scope remains out-of-phase.

</decisions>

## Existing Code Insights

### Reusable Assets
- `render_regime_card` in `app.py` already supports compact vs expanded rendering patterns.
- `format_oi_impact` and `build_card_fields` in `engine/report/card_model.py` provide canonical wording seams.

- `app.py`: scorecard compact/default fields, methods expander, OI table rendering, Evolution headline row.
- `engine/config.py` + `engine/compute.py`: 14 DTE primary framing source and downstream summary wiring.
- `engine/report/report.py`: mirror trust wording and concise assumptions for email parity where applicable.

<specifics>
## Specific Ideas

- Prefer concise trust labels (`history`, `building`, `model`, `oi`, `market`) over long caveat prose.
- OI impact story should prioritize concentration shifts (`vs 5d Avg`) and not just raw OI magnitude.
- Evolution summary row should answer: “Which dimension moved most today, and in what direction?”

</specifics>
