# Phase 16.5: OI Depth Expansion - Context

**Gathered:** 2026-06-22
**Status:** Ready for planning

<domain>
## Phase Boundary

Surface richer open-interest analytics in the Positioning tab and daily email:
expiry concentration (top expirations by OI), day-over-day expiry-level OI change,
put/call OI split per expiry, and parameter-free large-block flagging. All raw
labeled numbers — no scoring, no categorical labels, no trade prescription.

New infrastructure: `engine/data/oi_history.py` store (same pattern as surface_history).
All new compute in the engine layer. Display layers remain pure renderers.
</domain>

<decisions>
## Implementation Decisions

### OI History Store
- **D-01:** Create `out/oi_history/oi_{ticker}.parquet` — new dedicated store written
  by `run_daily` each trading session. Same isolated-module pattern as
  `engine/data/surface_history.py`. Store module: `engine/data/oi_history.py`.
- **D-02:** Granularity is **per-expiry aggregate** (not per-strike): columns
  `date, ticker, expiry, dte, call_oi, put_oi, oi`. One row per expiry per session.
  Lightweight (~10–30 rows/ticker/day). Bloomberg-swappable at the store writer only.
- **D-03:** Cold-start: when no prior session exists in the store for a ticker,
  day-over-day change shows "–" rather than NaN or an error.

### Per-Expiry Data Pipeline
- **D-04:** Add `expiry_oi_df` to `compute_ticker()` return dict alongside `s_df`/`p_df`.
  Engine computes per-expiry aggregates; display layers are pure renderers — they do
  not aggregate from raw chain.
- **D-05:** `expiry_oi_df` columns: `expiry, dte, call_oi, put_oi, oi, pct_of_total,
  put_call_ratio`. Sorted by `oi` descending. Filtered to ≤90 DTE (same cap as
  `config.GEX_MAX_DTE` — the dealer-relevant tenor).
- **D-06:** Large-block flags (OI-04) live on `s_df`: add `is_top_decile` bool column
  (True where `oi >= s_df.oi.quantile(0.9)` within ≤90 DTE strikes). No new return key;
  reuses the existing struct.

### Positioning Tab Layout
- **D-07:** New `st.expander("OI by Expiry", expanded=False)` below the existing
  OI-by-strike chart + 42-session levels chart. Contains a table: expiry | DTE | OI |
  calls | puts | P/C ratio (top expirations sorted by OI). Does NOT restructure the
  existing layout — Phase 18 will relocate as needed during the 3-page reorg.
- **D-08:** Large-block strikes (is_top_decile) shown as a scatter annotation trace
  on the existing `plot_oi_by_strike()` chart — a small symbol at flagged strikes.
  Does not replace or modify the existing bar traces; adds a layer.

### Email OI Summary
- **D-09:** Each ticker's card block in the daily email is followed by a compact OI
  section: top 3 expirations by OI with columns expiry / OI / calls / puts / P:C ratio.
  Plain inline-CSS HTML table (matches existing email style). Lives between the ticker
  card and the next ticker — does NOT move inside the card.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `engine/gex/exposure_engine.py:strike_oi()` — already aggregates call_oi/put_oi/oi
  by strike from the raw chain df. Expiry aggregation is the same pattern one level up
  (groupby expiry instead of strike).
- `engine/data/surface_history.py` — full isolated parquet store implementation to copy
  for `engine/data/oi_history.py`.
- `plot_oi_by_strike()` in `analytics.py:586` — accepts s_df; adding an `is_top_decile`
  scatter trace requires one additional `go.Scatter` call with filtered df.

### Established Patterns
- `compute_ticker()` returns a result dict — new keys (`expiry_oi_df`) follow the same
  pattern as `s_df` (DataFrame key in the result dict).
- All per-ticker parquet stores are idempotent on re-run (today's rows replaced, not
  appended twice) — mirror this in `oi_history.py`.
- `run_daily.py` calls all store writers after `compute_ticker()` — OI store write goes
  in the same block as `save_surface_snapshot()`.

### Integration Points
- `compute_ticker()` → add `expiry_oi_df` + `is_top_decile` column on `s_df`
- `run_daily.py` → call `save_oi_snapshot(expiry_oi_df, ticker, date)` after existing saves
- `app.py` Positioning tab → read `data["expiry_oi_df"]`, render expander + annotated chart
- `engine/report/report.py` → read `expiry_oi_df` from result, add compact OI table after card

</code_context>

<specifics>
## Specific Ideas

- Expiry table columns: expiry (formatted date), DTE, OI (total, formatted with K suffix),
  calls, puts, P/C ratio. Only ≤90 DTE rows.
- Day-over-day change column in expiry table: Δ OI vs prior session from oi_history store.
  Shows "–" on cold-start (no prior session), otherwise signed integer (e.g. +12K / −3K).
- Large-block annotation: small marker symbol (e.g. triangle-up) at flagged strike bars.
  Legend entry "large block (top 10%)". Keep annotation subtle — the bars are the main story.
- Email OI table: same 5 columns (expiry, OI, calls, puts, P:C). Top 3 rows only. No images.

</specifics>
