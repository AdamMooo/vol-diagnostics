### `engine/report/png_export.py` (utility, transform)

**Analog:** itself — `export_png()` (full file, lines 1-45).

**Full current implementation:**
```python
def export_png(
    fig: go.Figure,
    ticker: str,
    surface_type: str,
    date: datetime.date,
    out_dir: Path | None = None,
) -> Path:
    out_dir = out_dir or (Path(__file__).resolve().parents[2] / "out")
    out_dir.mkdir(parents=True, exist_ok=True)

    fig.update_layout(scene=dict(camera=dict(eye=config.KALEIDO_CAMERA_EYE)))

    filename = f"{ticker.lower()}_{surface_type}_{date.strftime('%Y%m%d')}.png"
    png_path = out_dir / filename

    fig.write_image(str(png_path), format="png")
    return png_path
```
D-06's scale-factor bump is a `scale=` kwarg on `fig.write_image(...)` (plotly/kaleido's native resolution multiplier — e.g. `fig.write_image(str(png_path), format="png", scale=2)`), or a `width=`/`height=` bump — the exact mechanism should follow whichever plotly/kaleido already exposes (check installed plotly version's `write_image` signature; kaleido supports `scale` directly). Precedent for "config-driven visual constant applied at every export call" is `config.KALEIDO_CAMERA_EYE` (`engine/config.py:204-208`) — the new scale factor should be a **named config constant** (e.g. `KALEIDO_SCALE`) documented the same way (one-line rationale + empirical reasoning), not a magic number inline, matching this file's own convention of pulling `KALEIDO_CAMERA_EYE` from `config` rather than hardcoding.

**Config precedent to copy exactly** (`engine/config.py:202-208`):
```python
# ── PNG export (kaleido) ───────────────────────────────────────────────────────

KALEIDO_CAMERA_EYE: dict[str, float] = {"x": 1.5, "y": -1.5, "z": 0.8}
"""Pinned isometric-style camera for 3D vol surface PNG exports.
Applied before every write_image() call so all attachments look consistent.
eye=(1.5, -1.5, 0.8) gives a readable perspective: moderate elevation, slight
front-right offset that shows both the skew gradient and the DTE term structure."""
```

**Docstring convention to preserve** (line 1): `"""PNG export from Plotly figures via kaleido. Callers own failure handling — this raises."""` — this file deliberately never catches exceptions (callers in `run_daily.py` wrap each call in their own try/except per-ticker, see `_build_png_attachments`/`_build_price_level_attachments`). D-06's change must not add a try/except here.

### `engine/data/data_loader.py` (service, request-response)

**Analog:** itself — `load_chain()` (lines 54-126) and `ChainSnapshot` (lines 30-38).

**`ChainSnapshot` dataclass — extend here if a filter-drop field or true timestamp is added:**
```python
@dataclass
class ChainSnapshot:
    ticker: str
    spot: float
    as_of: datetime.date
    chains: pd.DataFrame  # columns: expiry, strike, type, oi, iv, bid, ask
    iv30: float = 0.0            # CBOE 30-day implied vol for the underlying
    price_change_pct: float = 0.0  # underlying day % change
```
D-07 needs a new field here, e.g. `filter_drop_pct: float | None = None`, following the existing convention of documented default-valued fields (`iv30`, `price_change_pct`) added incrementally to this dataclass without breaking existing callers.

**Filter-drop computation site — inside `load_chain`'s row-building loop** (lines 90-121):
```python
    rows: list[dict] = []
    for opt in data["options"]:
        parsed = _parse_symbol(opt["option"], ticker)
        if parsed is None:
            continue
        expiry, side, strike = parsed

        dte = (expiry - today).days
        if dte < min_dte:
            continue

        oi = int(opt.get("open_interest") or 0)
        iv = float(opt.get("iv") or 0.0)

        if oi < min_oi or iv <= 0 or iv > max_iv:
            continue

        rows.append({...})
```
D-07's spec is "Filters removed X% of raw chain OI" — this means the percentage is OI-weighted (sum of OI on dropped contracts / sum of OI on all contracts), not a simple contract-count ratio. The accumulation needs two running totals (raw total OI across all parsed contracts before the `min_oi`/`iv`/`max_iv` filter, and OI actually kept) computed in this same loop, then `filter_drop_pct = (raw_oi_total - kept_oi_total) / raw_oi_total * 100` after the loop, passed into the returned `ChainSnapshot`. Note the existing `min_dte` filter (0DTE exclusion) is a *separate, intentional, locked* exclusion (see the `min_dte` docstring, lines 65-69) — CONTEXT's wording ("min_oi/max_iv filter drop ratio") suggests 0DTE-excluded contracts should NOT count toward the drop ratio; only `min_oi`/`iv<=0`/`max_iv` drops should. Track raw OI starting *after* the `dte < min_dte` continue, not before, to keep the ratio scoped to what CONTEXT actually asked for.

**Return-site pattern to extend** (lines 123-125):
```python
    chains = pd.DataFrame(rows)
    return ChainSnapshot(ticker=ticker, spot=spot, as_of=today, chains=chains,
                         iv30=iv30, price_change_pct=price_change_pct)
```

**No true wall-clock timestamp currently exists** — `as_of` is the session date only (line 88: `today = today if today is not None else datetime.datetime.now(ET).date()`), and the CBOE JSON payload (per current parsing, lines 76-84) is never checked for a fetch-time/quote-time field. If the D-01 display format `16:15 ET` is kept literally, a new `datetime.datetime.now(ET)` capture at fetch time (near line 72-73, right around the `requests.get` call) is needed as a genuinely new field — there is no existing analog for this in the codebase; `engine/session.py`'s `ET` timezone object (`engine/session.py:17`, `ET = pytz.timezone("America/New_York")`) is the one piece to reuse. Flag this ambiguity for the planner: either (a) add a real fetch-timestamp field, or (b) simplify D-01's displayed format to date-only (drop `16:15 ET`) since that's what `as_of` actually is today — this is a planning-time decision, not a coding one.

Relevant existing formatter to imitate for any new unsigned-percentage formatting need (D-07):
```python
def _fmt_pct(val: float | None, signed: bool = True, dp: int = 1) -> str:
    if val is None:
        return "—"
    sign = "+" if signed and val >= 0 else ""
    return f"{sign}{val:.{dp}f}%"
```
(`engine/report/card_model.py:38-42`) — this already supports `signed=False` for exactly the unsigned-percentage case D-07 needs (`_fmt_pct(filter_drop_pct, signed=False)` renders `"12.3%"` with no `+`). Import this via the existing `from engine.report.card_model import (...)` block in `report.py` rather than writing a new local formatter — closer look shows `report.py` already imports `_fmt_pct as _fmt_signed_pct` (line 17) but that's an aliased *signed* usage; a second import of the same function under its own name, or a call through the existing alias with `signed=False`, both work — do not duplicate the format string.

## Shared Patterns

### Inline-style-only HTML (Outlook COM safety)
**Source:** `engine/report/report.py` (module docstring, lines 1-10, and every table/div throughout)
**Apply to:** All new HTML fragments in `report.py` (D-01, D-02, D-05, D-07)
```python
_SANS = "font-family:Arial,Helvetica,sans-serif;"
_MONO = "font-family:Consolas,'SF Mono',Menlo,monospace;"
```
No `<style>` blocks, no `@media` queries, no external CSS — every visual property is an inline `style="..."` attribute. This is a hard constraint (Outlook desktop's Word rendering engine ignores anything else), not a preference.

### Cold-start / graceful omission
**Source:** `engine/report/report.py:evolution_section_html` (lines 324-339) and `build_email`'s consumption of it (lines 488-493); also `_ticker_card`'s `error` branch (lines 133-143) and `_key_levels_block`'s per-row `if X is not None` guards (lines 111-122)
**Apply to:** D-01 (as_of), D-07 (filter-drop line) — omit the element entirely when the source value is `None`; never render "—" or "N/A" for these two (that's reserved for card *fields*; header/footer chrome either shows real data or doesn't show at all, per the existing evolution-section precedent).

### Compute-once-thread-through (canonical parity seam)
**Source:** `engine/compute.py:compute_ticker` — wall-shift block (lines 274-278) and credibility-gated read-inputs block (lines 280-297); enforced project-wide per `.planning/phases/18-3-page-reorg-email-parity-gating/18-CONTEXT.md` D-13–D-16
**Apply to:** `data_loader.load_chain` → `compute.compute_ticker` → `summary` dict → `report.build_email`. Never compute `as_of` or `filter_drop_pct` inline inside `report.py` — both must already be plain values sitting on the `r` dict (a summary) by the time `report.py` touches them, matching the project rule "renderers do no I/O or heavy calculation."

### Config-driven visual constants (not magic numbers)
**Source:** `engine/config.py:193-208` (`PALETTE`, `KALEIDO_CAMERA_EYE`)
**Apply to:** D-06's kaleido scale factor — add a new named constant to `engine/config.py` (e.g. `KALEIDO_SCALE_FACTOR` or similar), documented with the same one-line-rationale docstring convention, rather than hardcoding a number in `png_export.py`.

### Mocked-I/O test pattern for compute.py threading changes
**Source:** `engine/tests/test_compute_oi_wiring.py` — `_make_mock_result()` helper (lines 11-93) patches every I/O boundary (`load_chain`, `add_greeks`, `compute_gex`, etc.) via `mock.patch.object(compute_mod, ..., return_value=...)` and asserts on the returned `summary`/`s_df` dict keys.
**Apply to:** New tests verifying `summary["as_of"]` and `summary["filter_drop_pct"]` are threaded through `compute_ticker` — extend this same mocking pattern (set `fake_snapshot.as_of = <a real date>` instead of `None` at line 45, and add a `filter_drop_pct` attribute to the mock snapshot) rather than writing a fresh test harness.

### HTTP-fetch mocking for data_loader tests
**Source:** `engine/tests/test_vol_index.py` (lines 50-99) — `patch("engine.data.vol_index.requests.get", return_value=mock_resp)` where `mock_resp` is a `MagicMock` with `.status_code`, `.text`/`.json()`, `.raise_for_status`.
**Apply to:** No dedicated `data_loader.py` test file currently exists (only indirect coverage via `compute.py`'s mocked-`load_chain` tests). If D-07's filter-drop-ratio logic in `load_chain` needs direct unit coverage, mock `engine.data.data_loader.requests.get` returning a fake CBOE JSON payload (`{"data": {"current_price": ..., "options": [...]}}`) the same way `test_vol_index.py` mocks its CSV fetch, rather than inventing a new mocking convention.

### HTML assertion-style tests for report.py additions
**Source:** `engine/tests/test_report.py` — throughout (e.g. `test_evolution_section_cold_start`, `test_png_note_present_when_set`/`test_png_note_absent_when_none` at lines 160-170, 225-235)
