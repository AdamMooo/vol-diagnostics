<decisions>
## Implementation Decisions

### Header block
- **D-01:** Placement of the new snapshot-timestamp line and methodology caveat banner, relative to the existing title+date section header, is **Claude's discretion** — pick whichever reads cleanest once drafted (directly below title, or below the Evolution section, above Cards).
- **D-02:** Snapshot-timestamp and methodology caveat are **two visually distinct lines**, not merged — the timestamp/data-freshness facts and the methodology caveat are different kinds of information and should read as such (e.g. caveat gets a different visual treatment, such as a tinted background, from the timestamp line).

### Content priority order
- **D-03:** Keep the **current section order** — Evolution → Cards → failed-ticker note → PNG-fallback note → footer. The "surfaces > walls > OI > gamma" priority language in ROADMAP success criteria #1 refers to **field-level priority within each card**, already implemented via `COMPACT_PRIMARY_LABELS` in `card_model.py` (Net GEX already demoted out of the primary row per the 2026-07-13 operator note). Do not reorder top-level sections.
- **D-04:** PNG attachment order within each ticker is **unchanged** — not part of this remodel's scope.

### Mobile-safe layout
- **D-05:** Shrink the email body to a **fixed narrow width (~375-400px)**, replacing the current fixed 720px table (`report.py:538`). No responsive `@media` queries — Outlook desktop (Word rendering engine) ignores them, and a single reliable fixed width beats a responsive layout that only half the client base honors.
- **D-06:** **Increase the kaleido PNG export resolution/scale factor** for chart attachments so they stay legible when viewed zoomed-in on a phone, at the same display width. No change to display width itself.

### Filter-drop transparency
- **D-07:** The new "Filters removed X% of raw chain OI" line goes in the **existing `methodology_footer` block**, grouped with the other caveat/assumptions text — matches where the original 2026-05-11 audit item specified it ("surface in email footer line").

### Claude's Discretion
- Exact placement of the header block elements (D-01).
- Exact wording/visual treatment (tint, border, spacing) distinguishing the caveat banner from the timestamp line (D-02).
- Exact kaleido scale factor for D-06.
- Fixed-width pixel value within the ~375-400px range (D-05).

### Folded Todos
- **Snapshot timestamp in header** (from `.planning/todos/pending/2026-05-11-v3-2-pre-distribution-hardening.md`) — ship-blocker from the 2026-05-11 audit, never implemented. Thread `ChainSnapshot.as_of` through `compute_ticker` → summary → `report.build_email()`; display as a timestamp line (see D-01/D-02).
- **Methodology caveat banner** (same source) — ship-blocker from the same audit, never implemented. Move the "GEX magnitude is methodology-specific" caveat into its own banner (see D-01/D-02) rather than only living in the 10px footer.
- **Filter-drop transparency** (same source) — high-value gap, never implemented. Log `min_oi`/`max_iv` filter drop ratio in `data_loader.load_chain`; surface per D-07.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `_section_header()` in `report.py` already builds the title+date header — extend rather than replace for D-01.
- `methodology_footer` block (report.py ~480-513) already has a two-tier "Quick assumptions" / "Deep methodology details" structure — D-07's filter-drop line fits the "Quick assumptions" tier.
- `evolution_section_html()` already handles cold-start omission (returns empty string when no evolution data) — same conditional-omission pattern applies to any new header elements if `as_of` or filter-drop data is unavailable.

### Established Patterns
- Fixed-width, inline-style HTML tables throughout `report.py` (no external CSS, no `<style>` blocks) — required for Outlook COM rendering reliability; D-05 must stay within this constraint (inline width attributes, not a `<style>` media query).
- Cold-start messaging is explicit, never silent (per Phase 18 GATE-02) — any new header content must degrade gracefully (omit, not blank/NaN) when `as_of` or filter-drop data isn't available.
- Card values are precomputed in `engine/compute.py`; renderers (`report.py`, `app.py`) do no I/O or heavy calculation — D-01/D-07 data must be threaded through `compute_ticker()`'s summary dict, not computed inline in `report.py`.

### Integration Points
- `engine/compute.py:compute_ticker()` — needs new summary keys for `as_of` (already exists on `ChainSnapshot`, needs threading) and filter-drop ratio (needs computing in `data_loader.load_chain()` and threading through).
- `engine/report/report.py:build_email()` — header block insertion point (~line 538-546) and `methodology_footer` (~line 480) are the two edit sites for D-01/D-02/D-07.
- `engine/report/png_export.py` — kaleido export call site for D-06's scale-factor bump.
