## OI History Store

| Option | Description | Selected |
|--------|-------------|----------|
| New store out/oi_history/ | New out/oi_history/oi_{ticker}.parquet written by run_daily each session. Per-expiry aggregate. Same isolated-module pattern as surface_history. Day-over-day becomes real from day 1 of accumulation. | ✓ |
| Skip / always show – | Don't build a store. Day-over-day column always shows –. Simpler, but feature is hollow. | |

**Granularity question:**

| Option | Description | Selected |
|--------|-------------|----------|
| Per-expiry aggregate | date, ticker, expiry, dte, call_oi, put_oi, oi — one row per expiry. Lightweight. | ✓ |
| Per-expiry + per-strike | One row per (expiry, strike). Richer, ~10-50x more rows. | |

**User's choice:** New store, per-expiry granularity.
**Notes:** None — fast confirmation both times.

## Per-Expiry Data Pipeline

| Option | Description | Selected |
|--------|-------------|----------|
| Add expiry_oi_df to compute_ticker() | Engine computes expiry aggregates. Display layers stay pure renderers. Consistent with architecture. | ✓ |
| Pass raw chain df | compute_ticker() adds raw_chain_df. Display layers compute expiry aggregates. Breaks compute-layer boundary. | |

**expiry_oi_df scope question:**

| Option | Description | Selected |
|--------|-------------|----------|
| Expiry aggregates only | Columns: expiry, dte, call_oi, put_oi, oi, pct_of_total, put_call_ratio. ≤90 DTE. | ✓ |
| Expiry aggregates + large-block flags | Also add is_large_block to expiry_oi_df. | |

**Large-block flags:** Claude discretion — add `is_top_decile` column to `s_df` directly (no new return key).

**User's choice:** expiry_oi_df in compute_ticker() with expiry aggregates only; large-block on s_df.
