### Human Verification Required

### 1. Dashboard OI by Expiry Expander — Layout and Δ OI Behavior

**Test:** Open `streamlit run app.py`, navigate to Positioning tab for any ticker (SPY recommended). Locate the "OI by Expiry" expander.
**Expected:** Expander is collapsed by default, positioned below the "γ-flip & walls — model derivation" expander. Opening it shows a table with columns: Expiry / DTE / OI / Δ OI / Calls / Puts / P/C Ratio. On cold start (no oi_history parquet yet), the Δ OI column shows "–" for all rows. OI values use K-suffix formatting (e.g. "142K").
**Why human:** Visual layout, collapse state, column ordering, and K-suffix formatting cannot be confirmed by grep alone.

### 2. OI-by-Strike Chart Large-Block Annotation

**Test:** In the same Positioning tab, inspect the OI-by-Strike chart.
**Expected:** Gold triangle-up markers appear at strikes in the top 10% of OI (within ≤90 DTE). Legend shows "large block (top 10%)". When all OI is below the decile threshold (unlikely for SPY), no markers appear and no error is raised.
**Why human:** Plotly scatter overlay visual correctness requires browser rendering; automated test confirms trace presence in the Figure object but not pixel-level appearance.

### 3. Daily Email OI Table + Parquet Store Write

**Test:** Run `python -m engine.run_daily --dry-run` from the project root. Open the generated HTML file in `out/`. Then check `out/oi_history/` for parquet files.
**Expected:** HTML email shows each ticker card followed by an "OI BY EXPIRY" section with 3 rows (top 3 expirations by OI, columns: Expiry / OI / Calls / Puts / P:C Ratio). After the run, `out/oi_history/oi_SPY.parquet`, `oi_QQQ.parquet`, `oi_IWM.parquet` all exist.
**Why human:** Requires live CBOE data fetch and actual email HTML render; --dry-run is a runtime operation not covered by unit tests.
