# Milestone v3.0: GEX Interactive Dashboard

**Status:** ✅ SHIPPED 2026-05-06
**Phases:** 1–4
**Total Plans:** 10

## Overview

Extended the GEX module from a daily HTML email into a live Streamlit dashboard with second-order Greeks (Vanna, Charm), PM-facing flow analytics (delta-hedge $/1%, vs-yesterday regime comparison), and a historical context tab. Email pipeline preserved unchanged; Streamlit is additive.

## Phases

### Phase 1: Greeks Engine

**Goal:** The Black-Scholes engine computes Vanna and Charm per contract with correct numerical guards
**Depends on:** Nothing (first phase)
**Plans:** 2 plans

Plans:
- [x] 01-01: Add bs_vanna(), bs_charm(), T_MIN to greeks_engine.py; extend add_greeks()
- [x] 01-02: Create gex/tests/ pytest suite covering vanna, charm, 0DTE guard, and add_greeks()

**Details:**
Added `bs_vanna()` and `bs_charm()` to `gex/greeks_engine.py` alongside existing `bs_gamma()`. `T_MIN = 1/365` guards charm divide-by-zero on 0DTE. `add_greeks()` extended to enrich chain DataFrames with vanna and charm columns. 31 tests; fixed scalar broadcast bug in vanna/charm when iv and T are scalar but strike is an array.

### Phase 2: Exposure + PM Flow

**Goal:** Exposure aggregates include VEX and CHEX by strike; delta-hedge flow and vs-yesterday labels appear in the email summary table
**Depends on:** Phase 1
**Plans:** 4 plans

Plans:
- [x] 02-01: Add compute_vex, compute_chex, strike_vex, strike_chex to exposure_engine.py; extend summarise()
- [x] 02-02: Extend save_snapshot() with vanna_exposure; add load_yesterday() and _classify_vs_yesterday() to validation.py
- [x] 02-03: Wire VEX/CHEX/flow/vs-yesterday into process_ticker() in run_daily.py; update email table columns in report.py
- [x] 02-04: pytest suite for all Phase 2 new functions

**Details:**
VEX = `sign * vanna * oi * 100 * spot * 0.01`. CHEX analogous for charm. `delta_hedge_flow = net_gex / (spot * 0.01)`. `load_yesterday()` returns prior trading session row (not calendar −1). vs-yesterday labels: UNCHANGED / FLIPPED / INTENSIFIED / EASED. Parquet schema extended with `vanna_exposure`; old rows get NaN without error.

## Milestone Summary

**Key Decisions:**
- Vanna over Vomma — delta shift per vol point is PM-readable; Vomma is not
- Streamlit additive — email pipeline (run_daily.py → Outlook COM) stays intact
- Phase order strictly 1→2→3→4 — each phase is a hard dependency on the prior
- No new data sources — yfinance + existing parquet only through v3.0

**Issues Resolved:**
- Phase 2: zero_gamma_level in parquet schema — confirmed present, no migration needed
- Phase 3: yfinance 429 on cold load — mitigated with per-ticker cache ttl=300 + serial fetch + sleep(0.3)
- Phase 4: Event study insufficient history — gated at 20 sessions minimum with info message

**Issues Deferred:**
- Phase 3 UAT: 4 pending human scenarios (partial)
- Phase 3 verification: human_needed items

**Technical Debt Incurred:**
- Zero test coverage on data_loader.py, report.py, emailer.py, run_daily.py, analytics.py chart functions
- American-style options (IWM) use European BS model — acknowledged with early exercise risk signal
