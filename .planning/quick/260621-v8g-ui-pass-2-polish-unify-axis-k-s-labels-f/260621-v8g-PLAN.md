CHANGE B — wrap interactive sections in @st.fragment:

Streamlit 1.57 supports @st.fragment. Wrap three functions. Define them just
above the `if sel_index:` block (around line 354).

Define three fragment-wrapped functions that encapsulate the heavy widget
sections currently inside `with tab_surface:`, `with tab_evolution:`, and
the `sub_today` / `sub_compare` sub-tabs. The simplest structure that avoids
rewriting the full inline body is:

  @st.fragment
  def _surface_today_section(selected_all, all_data):
      [move the with sub_today: block body here]

  @st.fragment
  def _surface_compare_section(selected_all, all_data):
      [move the with sub_compare: block body here]

  @st.fragment
  def _evolution_section(selected_all, all_data):
      [move the with tab_evolution: block body here, excluding the
       outer `with tab_evolution:` context manager which stays in place]

Then at the call sites:
  with sub_today:
      _surface_today_section(selected_all, all_data)
  with sub_compare:
      _surface_compare_section(selected_all, all_data)
  with tab_evolution:
      _evolution_section(selected_all, all_data)

The Positioning tab does NOT need a fragment — it has no interactive widgets
(no radios, no selectboxes) that would trigger reruns.

Do not fragment the card rendering or the top-level data fetch loop — those
must always run on full rerun (sidebar ticker select triggers a full rerun
intentionally).

Pass `selected_all` and `all_data` as arguments. Helper functions
(`_load_history_cached`, `_movie_payload_cached`, etc.) are module-level cache
functions and are available directly inside the fragment body without passing
them — they are not widget state.

Do not move the `sub_today, sub_compare = st.tabs(...)` line into the fragment.
Tabs are layout elements that belong at the outer scope. Only the content inside
each tab goes into its fragment function.
