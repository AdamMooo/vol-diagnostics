### 1. Fix broken matplotlib/Plotly mismatch in `run_gex.py`

The `save=True` branch (lines 53-63) calls `fig.savefig()` and `plt.close()` on
Plotly `go.Figure` objects — both will fail at runtime. The `save=False` branch
(lines 65-68) calls `plt.show()` on them — a no-op. `matplotlib` is imported at
the top solely for these broken calls.

Fix:

- Remove `import matplotlib`, `matplotlib.use("Agg")`, `import matplotlib.pyplot as plt`
  (lines 21-23).
- In the `save=True` block: replace `fig1.savefig(path1, dpi=150)` with
  `fig1.write_html(str(path1.with_suffix(".html")))`. Same for `fig2`.
  Update the path variables and print statements to use `.html` extension.
  Remove the two `plt.close()` calls.
- In the `save=False` block: replace the two stray `plot_strike_gex(...)` /
  `plot_gamma_profile(...)` calls that discard their return values, plus
  `plt.show()`, with `fig1.show()` and `fig2.show()`. Assign the return values
  first (`fig1 = plot_strike_gex(...)`, `fig2 = plot_gamma_profile(...)`).
- Remove the `matplotlib.use("TkAgg")` line (line 65) — only existed to switch
  backends for interactive display, irrelevant for Plotly.

Expected result: `python -m gex.run_gex --ticker SPY` writes
`out/gex_strikes_SPY_YYYY-MM-DD.html` and `out/gex_profile_SPY_YYYY-MM-DD.html`
instead of failing on `AttributeError: 'Figure' object has no attribute 'savefig'`.
