# Codebase Review & Cleanup Roadmap — gamma-omm
2026-06-29 · read-only review, no code changed · scope: full working tree (engine/ + app.py + runners/)

## Why this exists

Goal stated by owner: make gamma-omm **robust, professional, and presentable** — good enough to run
unattended for months, survive scrutiny on a trading desk, and show in job interviews. Docker/cloud
hosting is explicitly **parked** (cloud-connection pause) and out of scope here.

Three parallel reviewers covered: (1) engine computation/data core, (2) the unattended daily pipeline +
reporting, (3) dashboard UX/professionalism. This file is the synthesis — a pick-from menu, not a work order.
Nothing is changed yet.

## How to read

Findings are grouped into **six workstreams** by theme, not by reviewer, because the highest-leverage fixes
cut across files (e.g. one shared `session_date()` helper kills four separate findings). Each finding keeps
its original id so you can trace it: `C#`/`W#`/`I#` = engine core, `C-#`/`W-#`/`I-#` = orchestration,
`UX-#` = dashboard. Severity: **Critical** (wrong output / data loss / silent-bad-data / crash) ·
**Warning** (fragile, bites under bad input/failure) · **Info** (polish, optional).

## Workstream A — Data durability (do first)

The single biggest threat to "run unattended for months." CBOE snapshots have **no archive** — a bad write
or swallowed corruption loses irreplaceable history with no alarm.

- **`C-1` Critical — non-atomic parquet writes corrupt the store on interruption.**
  `validation.py:91`, `surface_history.py:62`, `oi_history.py:55`, `surface_evolution.py:199`, `vol_index.py:80`
  all do read-modify-`to_parquet(STORE)` in place. An interrupted write (sleep, power, disk hiccup on a
  `WakeToRun` box) truncates the file; the next read throws and every reader swallows it to an empty frame →
  **months of history silently read as gone.** Fix: one shared `_atomic_to_parquet(df, path)` helper
  (temp file in same dir → `os.replace`), swap all five call sites. Small diff, removes the corruption window.
- **`W-7` Warning — readers mask corruption as "cold start."** `run_daily.py:56`, `validation.py:115/127`,
  `surface_history.py:85`, `oi_history.py:77`, `surface_evolution.py:229` all `except Exception: return
  empty/None`. A corrupt parquet is indistinguishable from "no data yet." Fix: narrow the catch, emit a
  distinct `[CORRUPT]` marker, and propagate a flag so the report can say "history unavailable" instead of
  silently rendering cold-start text. Defense-in-depth for C-1.
- **`W-2` (orch) Warning — no cross-store consistency check.** `run_daily.py:181-198` writes scalar →
  surface → OI per ticker with no rollback; an interrupt between stores desyncs them invisibly (compare tab,
  evolution baseline, PNG diff all assume they agree). Fix: after the loop, assert each computed ticker has
  today's rows in all three stores; loud `[ERROR]` (+ email footer) if not. Full transactions are overkill;
  a post-write assertion is right-sized.
- **`W2` (engine) Warning — one bad vol-index symbol aborts the whole refresh.** `vol_index.py:33-37,64`
  only catches `RequestException`; a 200-with-HTML-body (`df["DATE"]` KeyError) crashes the fetch, and
  `refresh_vol_indices` has no per-symbol guard. Fix: broaden the catch to `except Exception` (function
  already documents "returns None on error") and wrap the per-symbol loop call.

## Workstream B — Date/session correctness (one helper, four bugs)

Highest leverage in the codebase: these all stem from **no single source of truth for "what session is
this."** Wrong-but-confident dates are the worst sin on a desk.

- **`C1` (engine) Critical — DTE computed off LOCAL date, snapshot keyed off ET date.**
  `data_loader.py:83,92` uses `date.today()` (local) for `dte`/`T_years`; `run_daily.py:161` keys the
  snapshot under `now(ET).date()`. On any tz-skewed/cloud/late-evening run, the whole chain's `T_years` is
  off-by-one vs the date it's filed under → silently wrong surface/skew/GEX/evolution. Fix: thread the run's
  ET session date into `load_chain` so the DTE basis and the snapshot key are the same date.
- **`W-3` (orch) Warning — session date is wall-clock, not calendar-derived.** `run_daily.py:60-64,161`
  uses `now(ET).date()`; a delayed/`StartWhenAvailable` catch-up after midnight files under the wrong day and
  evaluates `is_trading_day` for the wrong day. Fix: derive the session as the most recent NYSE session ≤
  `now(ET)`.
- **`W-8` (orch) Warning — duplicated, divergent session-date logic.** `app.py:488-507`
  (`_expected_latest_session`, calendar-correct) vs `run_daily.py:60-64` (wall-clock). The freshness banner
  checks a *different* "today" than the writer used. Fix: extract one `session_date(now_et)` helper in
  `engine/`, import it in both `run_daily.run` and `app._expected_latest_session` **and** `load_chain` (C1).
  This single helper resolves C1 + W-3 + W-8 + engine I-2/I-5.

## Workstream C — Fail loud, not silent (unattended honesty)

For an unattended desk tool, a blank metric must be distinguishable from a broken feed, and a "success" exit
must mean the deliverable actually shipped. Lower urgency *today* (owner's box is ET + Outlook-present) but
a hard prerequisite before any hosting / time away.

- **`C-3` (orch) Critical — email failure is swallowed; run reports success having sent nothing.**
  `run_daily.py:258-262` catches the send exception and exits 0 → Task Scheduler shows `LastTaskResult 0x0`,
  freshness banner still goes green (data *was* saved), nothing indicates the email channel is dead. Fix:
  on send failure `raise SystemExit(2)` (data already saved → C-2 resend recovers); keep observation append
  before send.
- **`C-2` (orch) Critical — idempotency guard conflates "data collected" with "run complete"; no resend
  path.** `run_daily.py:45-57,167` returns "already collected" when all tickers are in the scalar store, even
  if the email then failed. Operator can't resend without `--force`, and `--force` re-fetches a later
  intraday chain and overwrites every store. Fix: separate fetch/save gating from email; when "already
  collected," still load today's saved summaries and (re)send rather than returning immediately.
- **`W-6` (orch) + `W6` (engine) Warning — vol-index feed-down degrades VRP/term/VVIX silently.**
  `run_daily.py:174-178` → `compute.py:232-246` returns None for `vrp/vrp_pct/term_ratio/vvix` on a CBOE
  outage, rendered as "—" with no banner; `vol_metrics.py:421-432,475-481` take `.iloc[-1]` with no
  staleness check so days-old term/VVIX shows as current. Fix: capture refresh success and pass a "vol-index
  feed unavailable / stale as of <date>" banner into `build_email` (reuse the `png_note` plumbing); add a
  staleness gate (return None / stale flag when older than N sessions) and optionally fold vol-index
  freshness into `health_check`.
- **`W-5` (orch) Warning — fire-and-forget Outlook `mail.Send()`.** `emailer.py:40-64` — return ≠ sent
  (sits in outbox if Outlook closes/offline). Out of scope to re-architect; the C-3 fix surfaces
  connect/dispatch failures. Optional: prefer the existing SMTP path on Windows too to drop the GUI
  dependency — flag as a separate change, not part of this pass.

## Workstream D — Wrong-number bugs (correctness of what's shown)

Numbers on the surface that are subtly or outright wrong. These undermine credibility the moment an
interviewer probes them.

- **`W-1` (orch) Warning — "What changed most today" feature is dead and always shows "insufficient
  history."** `app.py:192-201` falls off the end returning `None`; the dict that builds the row
  (`:226-228`) is mis-indented *below/outside* the function (unreachable). A shipped Evolution-tab feature
  silently never works. Fix: dedent `:226-228` into `_latest_evolution_row_cached`, delete the stranded copy.
- **`C-4` (orch) Critical — hard-indexed OI columns can crash the whole email.** `report.py:276,280`
  use `row["oi"]` / `row["put_call_ratio"]` while neighbors use `.get`; a schema drift → KeyError →
  propagates through `build_email` (no try/except at `run_daily.py:244`) → aborts the report *after*
  snapshots saved. Fix: `.get` with defaults + wrap `_oi_summary_table` so a bad sub-table omits instead of
  aborting; belt-and-suspenders wrap `build_email` to fall back to minimal text.
- **`W1` (engine) Warning — model-free expected-move drops the `e^{rT}` discount.** `vol_metrics.py:108-109`
  (and the parity forward at `:66`) → systematic understatement (~0.6% of variance at 5%/≤45DTE) a desk
  reviewer will spot. Fix: multiply the integrand by `exp(r*t)`, thread `r`/use `config.RISK_FREE_FALLBACK`.
- **`W3` (engine) Warning — `put_call_ratio` stores ~5e9 garbage for put-only expiries.**
  `exposure_engine.py:101` uses `call_oi.clip(lower=1e-6)` as denominator and persists the result to the OI
  parquet. Fix: `np.where(call_oi > 0, put_oi/call_oi, np.nan)` — honest "undefined."
- **`W4` (engine) Warning — displayed RV20/VRP scalar uses unadjusted snapshot spot.** `compute.py:202-210`
  computes RV20 from `hist["spot"]` (raw daily CBOE price, div/split discontinuities) once ≥21 snapshots
  exist, while the deep VRP *percentile* uses adjusted yfinance closes → the scalar and its percentile can be
  computed off different series and disagree. Fix: use the yfinance adjusted series for the displayed
  RV20/VRP scalar (or document the divergence).
- **`W5` (engine) Warning — `_compute_wall_shift` "5-session shift" is 5d or 4d depending on caller.**
  `compute.py:72-95` — in `run_daily` today's row isn't saved yet (true 5d), in Streamlit it is (4d,
  mislabeled "5d"). Fix: explicitly exclude the current session row before indexing.
- **`W7` (engine) Warning — `compute_net_delta` sign comment contradicts the math + dead OI branch.**
  `vol_metrics.py:497,505-510` — `openInterest` column branch is dead (loader only emits `oi`); the
  `call_delta - put_delta` sign convention's inline comment is the opposite of standard dealer-short framing
  and the value is shown at `app.py:911`. Fix: reconcile comment vs math with a one-line proof, drop the dead
  branch.
- **`W8` (engine) Warning — γ-flip returns the lowest-spot crossing, not the one nearest spot.**
  `analytics.py:50-59` — multi-crossing profiles can report a flip far from spot. Fix: among sign changes,
  prefer the one whose level is closest to current spot (pass spot in), or document intent.

## Recommended sequencing

1. **A (durability)** — protects the irreplaceable history; nothing else matters if the store can vanish.
2. **B (date helper)** — one helper kills the silent off-by-one + two more findings; correctness foundation.
3. **D + E together** — D makes the shown numbers correct, E makes them *look* professional. The interview
   payoff is the combination: a clean instrument showing numbers that hold up when probed.
4. **C (fail-loud)** — do before any extended time away / hosting.
5. **F (polish/cleanup)** — opportunistic; the `run_gex` docstring and the stale test count are quick
   interview-credibility wins worth grabbing early.

Each workstream is a natural GSD quick-fix or small phase. A/B/D are mostly `engine/` and well-tested
(regression risk low). E is `app.py` + `card_model.py` prose (near-zero risk, high visible payoff).

## Explicitly NOT doing (parked or rejected as churn)

- **Docker / cloud hosting** — parked by owner (cloud-connection pause). W-4 (fail-open auth) is the one
  thing flagged to fix *before* that un-pauses.
- **No** Poetry/uv/pyproject migration, linters, pre-commit hooks, Makefile/just, or CI — solo-dev
  minimal-tooling preference; `requirements.txt` stays.
- **No** big refactors — `I6` (RBF triplication) and the SMTP-over-Outlook swap are flagged as *optional
  separate* changes, not part of any robustness pass.
- **No** reintroduction of removed-for-rigor features (VEX/CHEX, wall clusters, ZGL flow magnitude,
  vs-yesterday classifier, event study, early-exercise flags, categorical regime label). The E cleanup
  *preserves* the intellectual-honesty labels; it only removes hand-holding prose.
